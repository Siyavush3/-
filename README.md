# Тренажёр оператора ДДС (АРМ-112)

Учебное ПО для подготовки операторов Службы 112 и дежурно-диспетчерских служб города Москвы с использованием ИИ.
Задача 9 «Лидеров цифровой трансформации», Департамент ГОЧСиПБ города Москвы / ГБУ «Система 112».

Работает в изолированном контуре без внешних сетей. Целевое железо — Intel Core i5 8–10 поколения,
8–16 ГБ ОЗУ, без видеокарты. Рабочие места — браузеры Chrome, Firefox, Яндекс.Браузер (можно в режиме киоска).

## Что умеет

| Роль | Возможности |
|---|---|
| **Обучающийся** | кабинет: назначенные задания, результаты с оценкой преподавателя, прогресс и прогноз, рекомендации, материалы; тренажёр **оператора 112** (входящий вызов голосом, разговор с заявителем — вопросы голосом через микрофон или кнопками, карточка 112 с опросной картой по классификатору) и **диспетчера ДДС** (копия АРМ-112: лента, карточки, статусы, доклады бригады голосом) |
| **Преподаватель** | занятия с живым монитором, критерии успешности и нормативы; генерация сценариев с эталоном, проверка и правка по комментарию, утверждение; группы и задания; экспертная оценка (в аудите); отчёт о занятии (печать/PDF, Excel, CSV); аналитика: инсайты, тепловые карты, прогноз с проверкой на истории; материалы |
| **Администратор** | учётные записи и роли; состояние компонентов и нагрузка; сервисы; настройки безопасности, копирования, журналов; резервные копии; журналы и отчёт об ошибках; статистика; контроль целостности; пакетное обновление сценариев; TLS |

**ИИ в тренажёре — объяснимый и работает на процессоре:** оценка действий по эталону (категории нарушений
из памятки ДДС и инструкции оператора 112), проверка текста (морфология русского языка: орфография,
оформление, факты с учётом словоформ), генерация сценариев с автоматическим эталоном, аналитика с
прогнозом результата и проверкой прогноза на истории, синтез речи заявителей и бригады (piper), распознавание
вопросов оператора голосом (Vosk со словарём разговора оператора).
Языковая модель — по желанию (`A112_LLM_URL`): перефразирует тексты, эталон не трогает.

## Что проверено

- **Автотесты:** 209 проверок pytest (сквозные сценарии по HTTP и WebSocket, сверка C-ядра с эталоном, оценка,
  генерация, аналитика, озвучка, распознавание речи, установщики) и тесты C-ядра (ctest); CI — Linux
  (Ubuntu 20.04, 22.04, 24.04) и Windows (MSVC), `.github/workflows`.
- **Нагрузка** (`tools/loadtest.py --cpus 4`, сервер ограничен 4 ядрами, как i5): 100 обучающихся в 20 занятиях,
  10 обрывов связи, 20 операторов задают вопросы голосом — все требования ТЗ выполнены: отклик p95 — 0,2 с,
  итог распознавания — 0,5 с после конца фразы ([docs/LOADTEST.md](docs/LOADTEST.md)).
- **Установка без интернета:** `ARM112-Setup.exe` (встроенный Python, C-ядро, голоса, распознавание) —
  установка, запуск сервера из установленной копии и удаление; zip-дистрибутив — скриптом `deploy/windows`.

## Быстрый старт

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements/server.txt   # Linux: .venv/bin/pip
.venv/Scripts/pip install -r requirements/tts.txt -r requirements/asr.txt      # озвучка и голос — по желанию
python tools/fetch_voices.py && python tools/fetch_asr.py                     # голоса и модель распознавания
python server/run.py --demo            # http://127.0.0.1:8112, демо-учётки — data/demo/accounts.json
python server/manage.py seed-history   # демо-история занятий для аналитики (по желанию)
```

Проверить всё в одиночку — [docs/QUICK_TEST.md](docs/QUICK_TEST.md).
Установка в учебном классе без интернета: Windows — `ARM112-Setup-<версия>.exe` (`python tools/make_setup.py`,
Python внутри), Ubuntu — zip-дистрибутив и `install.sh`; подробности — [deploy/README.md](deploy/README.md).


## Сборка C-ядра и тесты

Нужны CMake ≥ 3.16 и компилятор C11 (GCC ≥ 9, Clang, MSVC 2022); без ядра маршрутизация идёт через эталон на
Python с тем же результатом.

```bash
pip install -r requirements/dev.txt
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build --parallel
python -m pytest                                  # A112_REQUIRE_NATIVE=1 — ядро обязательно (так в CI)
```

Windows без Visual Studio: компилятор, CMake и Ninja — из PyPI (`requirements/toolchain.txt`), компилятор — `zig cc`:

```bash
.venv/Scripts/pip install -r requirements/dev.txt -r requirements/toolchain.txt
ZIG=$(.venv/Scripts/python -c "import ziglang, os; print(os.path.join(os.path.dirname(ziglang.__file__), 'zig.exe').replace(chr(92), '/'))")
.venv/Scripts/cmake -S . -B build -G Ninja -DCMAKE_MAKE_PROGRAM=.venv/Scripts/ninja.exe \
    -DCMAKE_C_COMPILER="$ZIG" -DCMAKE_C_COMPILER_ARG1=cc -DPython3_EXECUTABLE=.venv/Scripts/python.exe
.venv/Scripts/cmake --build build
```

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `A112_DB` | база: `sqlite:///var/arm112.sqlite` (по умолчанию) или `postgresql://user:pass@host/db` |
| `A112_VAR` | каталог данных сервера: база, журналы, копии, кэш озвучки (по умолчанию `var/`) |
| `A112_DATA` | каталог данных тренажёра (по умолчанию `data/`) |
| `A112_TTS=off` | не запускать фоновую озвучку; `A112_TTS_DIR`, `A112_VOICES` — кэш звука и голоса |
| `A112_ASR=off` | не загружать модель распознавания речи при старте (загрузится при первом микрофоне); `A112_ASR_MODEL` — каталог модели, `A112_ASR_THREADS` — потоков распознавания (2) |
| `A112_MATERIALS_DIR`, `A112_LOG_DIR`, `A112_BACKUP_DIR`, `A112_CONTENT_DIR` | где хранить материалы, журналы, копии, обновляемые сценарии |
| `A112_LLM_URL`, `A112_LLM_MODEL` | необязательная локальная языковая модель (OpenAI-совместимый API) |
| `A112_LIB` | путь к `libarm112` (по умолчанию `build/bin`) |
| `A112_REQUIRE_NATIVE=1` | тесты падают, если C-ядро не собрано |

Исходные документы заказчика, снимки стенда, текст инструкции пользователя АРМ-112 и переписка с заказчиком
в репозиторий не входят; всё нужное для работы (классификатор, справочник служб, учебные билеты) извлечено в `data/`.
