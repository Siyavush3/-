# Киоск на рабочем месте обучающегося

АРМ тренажёра открывается в браузере на весь экран: без адресной строки, вкладок и меню —
рабочее место выглядит как отдельная программа. Устанавливать на машину ничего не нужно,
кроме этой папки: браузер уже есть (ТЗ: Chrome, Яндекс Браузер или Firefox; на Windows
подойдёт и встроенный Edge).

| Файл | Что это |
|---|---|
| `arm112-kiosk.cmd` | запуск на Windows двойным щелчком (вызывает `arm112-kiosk.ps1`) |
| `arm112-kiosk.ps1` | запуск на Windows 10/11 |
| `arm112-kiosk.sh` | запуск на Ubuntu 20.04 и новее |
| `kiosk.conf` | адрес сервера и браузер — одна правка на весь класс |
| `waiting.html` | страница ожидания: показывается, пока сервер не ответит, затем сама открывает вход |

## Как это устроено

- У киоска **свой профиль браузера**. Режим включается, даже если обычный браузер уже открыт,
  а в киоске нет чужих вкладок, расширений и сохранённых данных.
- Первой открывается `waiting.html` с этого компьютера, поэтому киоск можно запускать раньше
  сервера — например, при входе в Windows. Страница проверяет сервер каждые 2 секунды.
- Звук включён без предварительного клика по странице: доклады бригады должны звучать сразу.
- **Выход — Alt+F4.**

## Настройка класса

1. Скопируйте папку `deploy/kiosk` на каждое рабочее место.
2. Впишите адрес сервера в `kiosk.conf`: `SERVER=http://<адрес сервера>:8112`.
3. Создайте ярлык и, если нужно, автозапуск:

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File arm112-kiosk.ps1 -Install -Autostart
```

Ubuntu:

```bash
bash arm112-kiosk.sh --install --autostart
```

`-Install` / `--install` — ярлык «Тренажёр ДДС» на рабочем столе (Windows) или в меню
приложений (Ubuntu); `-Autostart` / `--autostart` — запуск киоска при входе пользователя.
Сам киоск при установке не запускается.

## Параметры

| Windows | Ubuntu | Назначение |
|---|---|---|
| `-Server URL` | `--server URL` | адрес сервера |
| `-Browser auto\|chrome\|yandex\|edge\|firefox` | `--browser …\|chromium` | какой браузер; `auto` — первый найденный в этом порядке |
| `-BrowserPath ПУТЬ` | `--browser-bin ПУТЬ` | браузер в нестандартном месте |
| `-Window` | `--window` | окно приложения вместо полного экрана — для настройки рабочего места |
| `-ExtraArgs '--ключ'` | `-- --ключ` | дополнительные ключи браузера |
| `-DryRun` | `--dry-run` | только показать, что будет запущено |

Адрес сервера и браузер берутся по порядку: ключ командной строки, переменные окружения
`A112_SERVER` и `A112_BROWSER`, файл `kiosk.conf`, значения по умолчанию
(`http://127.0.0.1:8112`, `auto`).

## Что проверить на машинах класса

- **Яндекс Браузер**: он построен на Chromium и должен понимать те же ключи (`--kiosk`, `--app`),
  но проверить это можно только на машине, где он установлен. `-DryRun` покажет команду.
- **Firefox** не умеет «окно приложения», поэтому `-Window` открывает у него обычное окно.
- **Ubuntu со snap**: у Chromium и Firefox из snap профиль киоска лежит в `~/snap/<браузер>/common`
  — в скрытые каталоги домашней папки snap-браузеры не пишут.

## Чего киоск не делает

Киоск прячет интерфейс браузера, но **не запирает компьютер**: клавиша Windows, Alt+Tab
и Ctrl+Alt+Del работают. Для аттестации рабочее место закрывают средствами ОС:
в Windows — отдельной учётной записью с ограниченным доступом (Assigned Access, групповые
политики), в Ubuntu — отдельным пользователем с киоск-сеансом (например, `gnome-kiosk` или `cage`).
