# Установка и эксплуатация сервера тренажёра

Тренажёр работает в изолированном контуре: один сервер в локальной сети учебного класса, рабочие места
обучающихся и преподавателя — браузеры (Chrome, Firefox, Яндекс.Браузер), при желании в режиме киоска.

## Требования

| | Сервер класса | Рабочее место |
|---|---|---|
| Процессор | Intel Core i5 8–10 поколения (4 ядра) и выше | любой, где работает современный браузер |
| Память | 8 ГБ (16 ГБ — с озвучкой при занятиях); распознавание речи — ещё ~250 МБ | 4 ГБ |
| Диск | 2 ГБ под программу, голоса и модель распознавания + база, копии, журналы | — |
| ОС | Windows 10/11, Windows Server 2019+, Ubuntu 22.04/24.04 | Windows, Ubuntu |
| ПО | Python 3.11 (3.10–3.12); PostgreSQL ≥ 12 — по желанию | Chrome, Firefox или Яндекс.Браузер |
| Сеть | порт 8112/TCP открыт для рабочих мест | доступ к серверу по адресу и порту |
| Звук | — | колонки или гарнитура; для вопросов голосом — микрофон (гарнитура) |

Нагрузочный тест (`tools/loadtest.py`): 100 обучающихся, 20 одновременных занятий, 10 обрывов связи, 20 операторов
задают вопросы голосом — все требования ТЗ выполнены и на сервере, ограниченном 4 ядрами (отклик p95 ≤ 0,3 с,
итог распознавания — через 0,5 с после конца речи; см. `docs/LOADTEST.md`).

## 1. Дистрибутив (на машине с интернетом)

Для Windows — установщик **`ARM112-Setup-<версия>.exe`** (раздел 2): всё внутри, включая Python.
Собирается на Windows с Python 3.11 и [Inno Setup 6](https://jrsoftware.org/isinfo.php) (переменная `ISCC`,
ключ `--iscc` или переносимая копия в `dist/tools/innosetup`):

```bash
python tools/make_setup.py
```

Zip-дистрибутив — для Ubuntu и для установки на Windows скриптом PowerShell:

```bash
python tools/make_dist.py --platform windows     # или --platform linux
```

В `dist/arm112-<версия>-<платформа>.zip`: программа, собранное C-ядро (если собрано для этой платформы),
все Python-пакеты для установки без интернета (`wheels/`), голоса озвучки (`data/voices`, если они есть —
`python tools/fetch_voices.py`) и модель распознавания речи (`data/asr`, если она есть — `python tools/fetch_asr.py`).
Контрольная сумма — рядом, в `.sha256`. Для Windows без Python положите
в корень дистрибутива установщик `python-3.11.x-amd64.exe` — установщик тренажёра поставит его сам.

## 2. Установка на Windows

### Установщик ARM112-Setup.exe (рекомендуется)

Запустите `ARM112-Setup-<версия>.exe` (нужны права администратора) — мастер спросит папку (латиницей,
по умолчанию `C:\ARM112`), порт (8112) и пароль администратора `admin` (не короче 8 символов, буквы и цифры),
предложит автозапуск, правило брандмауэра и ярлык на рабочем столе. Интернет и Python на машине не нужны:
внутри — встроенный Python 3.11 со всеми пакетами, C-ядро, голоса и модель распознавания речи. Если в системе
нет среды выполнения Visual C++ (`msvcp140.dll`, нужна озвучке), установщик поставит её пакетом Microsoft.
Журнал настройки — `C:\ARM112\var\logs\install.log`. В меню «Пуск» — «Открыть тренажёр», «Запустить сервер
вручную», документация и удаление.

- **Обновление** — запустить установщик новой версии поверх: сервер остановится, программа обновится, база,
  учётные записи и результаты останутся.
- **Удаление** — «Удалить тренажёр» (или «Приложения» Windows): снимаются автозапуск и правило брандмауэра;
  базу, журналы и резервные копии (`var`) удаляет только по вашему подтверждению.
- **Без вопросов** (развёртывание): `ARM112-Setup-<версия>.exe /VERYSILENT /TASKS="service,firewall" /PORT=8112
  /ADMINPASSWORD=<пароль>`; без `/ADMINPASSWORD` — временный пароль, он в `var\logs\install.log`.
- **Без прав администратора** (показ на ноутбуке): `/CURRENTUSER` — установка в профиль пользователя
  (`%LOCALAPPDATA%\ARM112`), без автозапуска и брандмауэра; сервер — ярлыком «Запустить сервер вручную».

### Из zip-дистрибутива скриптом PowerShell

Распакуйте архив в папку **с путём латиницей** (например, `C:\Install\arm112`) и в PowerShell от имени
администратора выполните:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\install.ps1
```

Установщик: проверит Python, скопирует программу в `C:\ARM112`, поставит пакеты из `wheels` (с озвучкой и
распознаванием речи, если они есть в дистрибутиве; модель распознавания сверяется по SHA-256), создаст базу и
администратора (спросит пароль; Enter — временный со сменой при первом входе), снимет эталон целостности,
откроет порт 8112 в брандмауэре и зарегистрирует автозапуск — задачу планировщика `ARM112-Server` (от SYSTEM,
при сбое — перезапуск через минуту).

| Параметр | Назначение |
|---|---|
| `-Dir C:\ARM112` | папка установки — только латиницей: espeak-ng и openssl не открывают пути с кириллицей |
| `-Port 8112` | порт сервера |
| `-Db "postgresql://arm112:пароль@localhost/arm112"` | PostgreSQL вместо встроенной SQLite |
| `-Tls -ServerName 10.0.0.5` | HTTPS: сертификат для адреса сервера (см. «Защищённое соединение (TLS)») |
| `-Unattended` | без вопросов: администратору — временный пароль |
| `-NoService`, `-NoFirewall` | без автозапуска и без правила брандмауэра |
| `-DryRun` | только показать шаги |

Управление: `Stop-ScheduledTask ARM112-Server`, `Start-ScheduledTask ARM112-Server`; вручную — `C:\ARM112\start-server.cmd`.

## 3. Установка на Ubuntu 22.04/24.04

```bash
sudo apt install -y python3 python3-venv openssl        # из локального зеркала или заранее
unzip arm112-*-linux.zip && cd arm112-*-linux
sudo bash deploy/linux/install.sh
```

Установщик создаёт пользователя `arm112`, ставит программу в `/opt/arm112`, пакеты — из `wheels`, базу и
администратора, службу systemd `arm112` (перезапуск при сбое, запись только в свои данные) и открывает
порт в ufw, если он включён. Параметры: `--dir`, `--port`, `--db postgresql://…`, `--tls --server-name <адрес>`,
`--unattended`, `--no-service`, `--dry-run`. Управление: `systemctl status|restart|stop arm112`,
журнал — `journalctl -u arm112` и `/opt/arm112/var/logs`.

C-ядро для Linux собирается на машине сборки (`cmake -S . -B build && cmake --build build`, см. корневой
README); без него маршрутизация идёт через эталон на Python с тем же результатом, чуть медленнее.

## 4. PostgreSQL (по желанию)

```bash
sudo -u postgres psql -c "CREATE USER arm112 WITH PASSWORD 'пароль'"
sudo -u postgres psql -c "CREATE DATABASE arm112 OWNER arm112"
```

Адрес базы — параметр установщика `-Db` / `--db` (записывается в `start-server.cmd` / `/etc/arm112.env` как
`A112_DB`). Схема создаётся сама. Резервные копии PostgreSQL сервер делает через `pg_dump`, если он установлен.

## 5. Защищённое соединение (TLS)

```bash
python server/manage.py make-cert --host 10.0.0.5          # адрес сервера, можно несколько --host
python server/run.py --host 0.0.0.0 --certfile var/tls/arm112.crt --keyfile var/tls/arm112.key
```

Сертификат самоподписанный: установите `var/tls/arm112.crt` в доверенные корневые на рабочих местах
(или используйте сертификат ведомственного УЦ тем же `--certfile`). При HTTPS сервер отдаёт HSTS;
WebSocket занятий идёт по `wss://` автоматически. HTTPS нужен и для микрофона: браузер даёт его только защищённым
адресам (или в режиме киоска — см. раздел 7).

## 6. Первый вход и учётные записи

1. Откройте `http://<адрес сервера>:8112`, войдите администратором, смените временный пароль.
2. «Учётные записи» → создайте преподавателей и обучающихся; каждому выдаётся временный пароль.
3. Преподаватель создаёт группы («Группы и задания») и занятия; обучающиеся входят и попадают в кабинет.

Для показа есть демо-учётки (`python server/manage.py seed-demo`, пароли — `data/demo/accounts.json`) и
демо-история для аналитики (`seed-history`); на рабочем сервере их не создавайте.

## 7. Рабочие места обучающихся — режим киоска

Скопируйте `deploy/kiosk` на рабочее место, впишите адрес сервера в `kiosk.conf` и выполните
`powershell -ExecutionPolicy Bypass -File arm112-kiosk.ps1 -Install -Autostart` (Windows) или
`bash arm112-kiosk.sh --install --autostart` (Ubuntu). Подробности — `deploy/kiosk/README.md`.
Киоск разрешает микрофон для вопросов голосом без запроса и, если сервер работает по `http://`, объявляет его
адрес защищённым — только в своём профиле браузера.

## 8. Эксплуатация

| Задача | Как |
|---|---|
| Состояние, нагрузка, сбои | администратор → «Состояние», «Журналы» |
| Резервные копии | ежедневно в 03:00 (настройка), вручную — «Резервные копии» или `python server/manage.py backup` |
| Восстановление | остановить сервер → `python server/manage.py restore var/backups/<файл>.zip` → запустить |
| Обновление сценариев | администратор → «Настройки» → «Пакетное обновление» (zip с `scenarios/*.json`) |
| Обновление программы | режим обслуживания → резервная копия → остановить → распаковать новую версию поверх (кроме `var`) → `install.ps1`/`install.sh` → `manage.py integrity --write` |
| Целостность программы | «Настройки» → «Проверить целостность» или `python server/manage.py integrity` |
| Нагрузочный тест | `python tools/loadtest.py [--cpus 4]` — отдельный сервер на временной базе |

## 9. Частые вопросы

- **Озвучки нет, реплики текстом.** Нет голосов в `data/voices` или пакетов `requirements/tts.txt`; состояние —
  «Состояние» → «Озвучка». Тренажёр работает и без неё.
- **Windows: onnxruntime не загружается (msvcp140_1.dll).** Используйте версию из `requirements/tts.txt`
  (1.17.3) или установите Microsoft Visual C++ Redistributable.
- **Кнопка «Микрофон» недоступна или «распознавание не установлено».** Микрофон браузер даёт только по HTTPS, на
  компьютере сервера или в режиме киоска. Распознавание — пакеты `requirements/asr.txt` и модель в `data/asr`
  (`python tools/fetch_asr.py --check` сверит и распакует); состояние — «Состояние» → «Распознавание речи».
- **Путь с кириллицей.** Ставьте тренажёр в путь латиницей: espeak-ng и openssl на Windows не открывают такие пути
  (тренажёр обходит это сам, но установщик требует латиницу).
- **Браузер не пускает звук.** В обычном браузере — первый клик по странице включает звук (кнопка «Звук» подсказывает);
  в режиме киоска звук разрешён сразу.
