# Описание системы

Тренажёр АРМ-112 — учебная программа для подготовки операторов Службы 112 и диспетчеров дежурно-диспетчерских
служб (ДДС) города Москвы. Он воспроизводит рабочие места АРМ-112 — приём вызова и заполнение карточки 112,
работу службы с карточками — и оценивает действия обучающегося по правилам заказчика: памятке «Работа на АРМ-112
для ДДС» и инструкции пользователя модуля «Приём и обработка вызовов 112». Работает в изолированном контуре на
одном сервере учебного класса: Intel Core i5 8–10 поколения, 8–16 ГБ памяти, без видеокарты.

  │ · цикл событий: HTTP, WebSocket, движок занятий (шаг 0,2 с)          │

  └──┬───────────────────┬───────────────────────────┬───────────────────┘

  ┌──▼──────────────┐ ┌──▼──────────────────────┐ ┌──▼──────────────────────────────┐

  │ SQLite (WAL)    │ │ кэш звука, материалы,   │ │ реплики сценариев → WAV 8 кГц   │

| Часть | Что делает | Технологии |
|---|---|---|
| Сервер занятий | вход и роли, занятия, движок сценариев, оценка, отчёты, аналитика, администрирование; REST и WebSocket ([API.md](API.md)) | Python 3.11, FastAPI, uvicorn |
| Движок занятия | лента карточек ДДС и очередь вызовов 112 по серверному времени, автомат статусов реагирования, доклады бригады, заявитель-бот, монитор преподавателя | однопоточный детерминированный движок в цикле событий |
| C-ядро `libarm112` | маршрутизация карточки по классификатору происшествий (1283 кода, 58 служб) и справочнику служб; таблица правил загружается отображением файла в память | C11; сверка с эталонной моделью на Python — 524 882 сравнения |
| Хранилище | учётные записи, сеансы, аудит, занятия и журнал их событий, результаты, сценарии, группы, задания, материалы, настройки | SQLite (WAL) или PostgreSQL ≥ 12 — один SQL |
| Озвучка | реплики заявителей и доклады бригады «по телефонной линии»; синтез заранее, отдельным процессом с ограничением ресурсов | piper (VITS в ONNX), onnxruntime на процессоре |
| Распознавание речи | вопросы оператора 112 голосом: звук микрофона → текст фразы → вопрос заявителю | Vosk (Kaldi), малая русская модель, словарь разговора оператора |
| Веб-интерфейс | вход, кабинет, АРМ оператора 112, АРМ ДДС (копия АРМ-112), преподаватель, администратор, отчёт | HTML, CSS, JavaScript без внешних библиотек и шрифтов |

## 2. Как идёт занятие

1. Преподаватель создаёт занятие по утверждённому сценарию (или назначает задание группе — тогда обучающийся
   проходит его сам), задаёт темп, нормативы и критерии зачёта.
2. Обучающиеся входят; страница держит с сервером соединение WebSocket: токен — первым сообщением, команды —
   с номером. После обрыва связи страница досылает неподтверждённые команды, сервер отбрасывает повторы.
3. Движок выдаёт карточки и вызовы по серверному времени. C-ядро раскладывает карточку по службам: обучающийся
   ДДС видит только карточки своей службы. Оператору 112 звонит заявитель-бот, отвечающий по сценарию.
4. Каждое действие записывается в журнал событий занятия (`lesson_events`) с серверным временем — по нему
   строятся оценка, монитор преподавателя и отчёт.
5. По завершении — оценка по эталону сценария, зачёт по критериям, результаты в базе; обучающийся видит итог
   в кабинете, преподаватель — в итогах, отчёте и аналитике. Занятие, прерванное перезапуском сервера,
   помечается «прервано», его события сохраняются.

## 6. Искусственный интеллект

Правильный ответ всегда задают проверяемые правила заказчика — памятка ДДС, инструкция оператора 112,
классификатор; модели помогают там, где правила не дают результата. Всё работает на процессоре без видеокарты и
без внешних сетей.

| Компонент | Как работает | Как проверено |
|---|---|---|
| Оценка действий | сравнение с эталоном сценария: ДДС — 8 категорий нарушений памятки, включая ошибки в тексте; оператор 112 — 12 категорий (тип, признаки, адрес, обязательные поля, описание, нормативы, службы) | эталонное прохождение даёт 100 баллов; каждое нарушение — отдельный тест |
| Проверка текста | морфология русского языка (pymorphy3, словарь OpenCorpora): орфография с вариантами исправления, оформление, факты с учётом словоформ | ни одного ложного срабатывания на 94 текстах билетов; опечатки стенда находятся |
| Генерация сценариев | комбинаторика по классификатору и учебному справочнику адресов; эталон ДДС — по правилам памятки (чужая УК, чужой лифт, ГБУ «Автодороги», ОЭК, дубль, отказ после принятия) с объяснением и образцом комментария; правка карточки по комментарию преподавателя | сгенерированные сценарии проходят ту же проверку, что встроенные; образцы комментариев засчитываются оценкой |
| Аналитика и прогноз | прогноз следующего результата — сглаживание Холта с затуханием тренда; достоверность — пошаговая проверка на истории против прогноза «как в прошлый раз»; тепловые карты ошибок; инсайты | на кривых обучения (600 × 8 занятий, шум 3–8 баллов): средняя ошибка 6,2 балла против 7,2 у наивного прогноза; 80-процентный интервал накрывает факт примерно в 80% случаев |
| Рекомендации | правила по категориям ошибок с текстами памятки и инструкции; у каждой — параметры тренировки для генератора | тексты сверены с документами заказчика |
| Синтез речи | piper (VITS в ONNX): 3 русских голоса, у каждого заявителя свой темп; телефонная линия 8 кГц | 759 фраз встроенных сценариев — около 13 минут на одном ядре, пик памяти 414 МБ |
| Распознавание речи | Vosk, малая русская модель; словарь разговора оператора (~4300 словоформ); конец фразы — пауза 0,5 с; вопрос — по основам слов, устойчиво к ошибкам окончаний | нагрузочный тест: 20 операторов говорят на фоне 100 обучающихся — итог через 0,5 с после конца речи, вопрос верно в 96% фраз, 4% времени одного ядра |
| Языковая модель (необязательно) | локальный сервер с OpenAI-совместимым API (`A112_LLM_URL`): перефразирует текст карточки по комментарию, который правила не разобрали; ответ проверяется орфографией | без модели всё работает на правилах |

## 7. Безопасность

| Требование ТЗ | Как выполнено |
|---|---|
| Многоуровневая аутентификация | пароль (PBKDF2-SHA256, 200 000 итераций; политика сложности), временный пароль со сменой при первом входе, блокировка после неудачных попыток, сеансы с ограниченным сроком, повторный ввод пароля для опасных действий администратора |
| Разграничение доступа по ролям | администратор, преподаватель, обучающийся — права проверяются на каждом запросе и при подключении к занятию; преподаватель видит только свои группы и занятия, обучающийся — только свои результаты; администратор не вмешивается в учебный процесс |
| Защита каналов | HTTPS и WSS с сертификатом, HSTS; токен WebSocket передаётся первым сообщением, а не в адресе |
| Учёт действий пользователей | журнал аудита с цепочкой хешей; изменения оценок и настроек — с записью «было → стало» |
| Резервное копирование | ежедневно по расписанию и вручную; манифест SHA-256; проверка копии; восстановление командой |
| Целостность программы | эталон SHA-256 файлов программы, проверка из интерфейса администратора |
| Изолированный контур | без внешних обращений; установка без интернета; звук микрофона не сохраняется — только текст фразы |

## 8. Производительность и надёжность

Нагрузочный тест ([LOADTEST.md](LOADTEST.md)) на сервере, ограниченном 4 ядрами, как у i5: 100 обучающихся в
20 одновременных занятиях, 10 обрывов связи до 25 с, 20 операторов задают вопросы голосом. Все требования ТЗ
выполнены: 95% запросов — быстрее 0,3 с (ТЗ — 2 с), запись в базу — свыше 10 000 операций в секунду (ТЗ — 100),
аналитика — 0,02 с (ТЗ — 30 с), после обрывов ни одна команда не потеряна.

Надёжность: действия занятия досылаются после обрыва связи и не дублируются; события занятия сохраняются в базе
по ходу, а не в конце; озвучка идёт отдельным процессом — её сбой не затрагивает занятия; автозапуск сервера
перезапускает его при сбое; резервные копии — ежедневно.

## 9. Ограничения

- **Голоса озвучки** дообучены с модели lessac (исследовательская лицензия), у голоса ruslan данные некоммерческие:
  для эксплуатации их нужно заменить ([LIBRARIES.md](LIBRARIES.md)).
- **IP-телефония** эмулируется в браузере (звонок, голос заявителя и бригады); подключение к АТС (SIP) не входит.
- **Адреса** — учебный справочник из 7 районов; реального адресного реестра (ФИАС) в контуре нет.
- **Данные заказчика** (выгрузки базы Системы-112, статистика, журналы) не предоставлены: прогноз и генератор
  настроены на синтетических данных и перепроверяются на реальной истории — метрики показаны в интерфейсе.
- **Распознавание речи** проверено на синтезированных фразах; на живых голосах в классе точность нужно замерить,
  свободная речь вне словаря оператора не распознаётся.
- **Нагрузочный тест** выполнен на машине сборки с ограничением сервера 4 ядрами; на настоящем i5 его нужно
  повторить (`python tools/loadtest.py`).

Проектные решения и их история — [ARCHITECTURE.md](ARCHITECTURE.md), допущения — [ASSUMPTIONS.md](ASSUMPTIONS.md).
