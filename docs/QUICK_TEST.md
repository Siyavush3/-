# Как проверить тренажёр одному

Нужен один компьютер и один браузер. Вход хранится отдельно для каждой вкладки, поэтому преподаватель и
обучающийся открываются в соседних вкладках. Пароли демо-учёток — в `data/demo/accounts.json`.

```bash
python server/run.py --demo           # http://127.0.0.1:8112
```

## 1. Звонок в 112 — сами, без преподавателя (≈ 5 минут)

**Подготовка (один раз, вкладка 1 — `teacher`):** «Группы и задания» → создать группу «Проба» → отметить
«Иванов Иван» → «Сохранить состав» → справа сценарий «Вызовы из билетов: заполнение карточки 112»,
вызовов 2, норматив карточки 120 с → «Назначить группе».

**Звонок (вкладка 2 — `student1`):** после входа открывается кабинет → «Задания» → «Начать».

1. Звонит телефон (зелёная трубка мигает, звучит звонок) → «Принять вызов» или Enter.
   Заявитель говорит голосом, реплика — и текстом справа.
2. Кнопками разговора спросите «Адрес», «Как зовут», «Пострадавшие» — заявитель отвечает. Повторный вопрос
   об адресе — уточнённый адрес. **Или голосом:** «Микрофон: вкл» (Alt+M), браузер спросит разрешение — «Разрешить»;
   скажите «Назовите адрес», сделайте паузу — под разговором появится ««назовите адрес» → Адрес?», и заявитель
   ответит. На этом компьютере (`127.0.0.1`) микрофон работает сразу; с другого — только по HTTPS или в киоске.
3. Заполните карточку: ФИО и статус заявителя, адрес (улица, дом, подъезд, квартира), «Пострадавшие».
4. «Что случилось?» — начните вводить часть слова («пожар», «лифт») и выберите тип; пройдите вопросы опросной
   карты. Внизу появится полоса служб — они подобраны по классификатору.
5. Описание — главное в первых 100 символах. **Alt+S** — сохранить.
6. Сразу приходит разбор: балл, замечания по категориям и «как надо». Второй вызов — сам; после последнего
   задание завершается, итог — в кабинете → «Мои результаты» → «подробный отчёт».

Ошибитесь нарочно (другой дом, не тот тип, пустой статус, долгое заполнение) — каждая ошибка будет в разборе.

## 2. ДДС без спешки (≈ 10 минут)

В реальном темпе карточки идут каждую минуту, а первичный статус нужен за 30 секунд — для знакомства
это быстро. Поэтому:

**Вкладка 1 (`teacher`) → «Занятия»:** сценарий «ДДС района Щукино», темп «замедление ×3 (первое знакомство)»,
«Критерии успешности и нормативы» → норматив первичного статуса 90 с → «Создать занятие».
**Вкладка 2 (`student1`):** кабинет → «Перейти к занятиям» → «Войти». **Вкладка 1:** «Назначить роль всем» →
«Начать занятие».

Карточки приходят раз в три минуты. На каждую:

1. Откройте карточку и «Справку службы» (кнопка в полосе тренажёра): какие дома свои, какие — других УК,
   где лифты чужие, какие дворы — ГБУ «Автодороги», электрощитовые — ОЭК.
2. Своё — «Принята». Чужое — «Не принята» с комментарием: кто обслуживает и куда передана информация.
   Повтор той же ситуации — «Не принята», «дубль карточки …».
3. По принятым звонит старший бригады (голосом) — ставьте статусы по его докладам: «Начало реагирования» →
   «Прибытие» → «Проведение работ» → «Работы завершены», с комментарием. Если бригада сообщает, что это
   не ваша сеть, — «Отказ от выполнения работ» с комментарием.

**Вкладка 1:** монитор показывает просрочки; «Завершить занятие» → итог по категориям памятки →
«Отчёт о занятии».

## 3. Посмотреть правильную работу ДДС — автопилот (≈ 6 минут)

Бот-диспетчер проходит занятие строго по эталону, а вы смотрите:

```bash
python tools/demo_dds.py --tempo 0.5          # вдвое быстрее реального времени; --tempo 1 — как на смене
```

Скрипт создаёт занятие и пишет его номер. За 20 секунд до старта откройте в браузере `http://127.0.0.1:8112`,
войдите как **student2** и нажмите «Войти» у этого занятия — на экране АРМ будут появляться карточки,
«Принята» / «Не принята» с правильными комментариями и статусы после докладов бригады. Во второй вкладке
преподавателем виден монитор. В конце — итог бота (100 баллов) и ссылка на отчёт: там вся хронология
с секундами.
