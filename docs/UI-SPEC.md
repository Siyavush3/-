## 1. Общая раскладка и палитра

Три горизонтальные зоны, фиксированные по высоте, между ними — рабочая область в две колонки.

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ВЕРХНЯЯ ПОЛОСА: телефония (4 блока) │ идентификация карточки │ таймер     │
├─────────────────────────────┬────────────────────────────────────────────┤
│ ЛЕВАЯ КОЛОНКА               │ ПРАВАЯ КОЛОНКА                             │
│ заявитель · адрес · описание│ признаки/опросная карта                    │
├─────────────────────────────┴────────────────────────────────────────────┤
│ НИЖНЯЯ ПОЛОСА: список оповещения (службы) │ действия                     │
└──────────────────────────────────────────────────────────────────────────┘
```

Палитра, снятая со скриншотов:

| Роль | Цвет |
|---|---|
| Фон страницы, панели | почти белый / очень светлый серый |
| Разделители, рамки полей | светло-серый, поля — подчёркивание снизу, не рамка |
| Подписи полей | серый, мелкий |
| Значения полей | тёмно-серый, крупнее подписи |
| Выбранный признак (кнопка-тумблер) | насыщенный синий, белый текст |
| Невыбранный признак | белый фон, серая рамка, тёмный текст |
| Заголовок панели опросной карты | почти чёрный, белый текст, подчёркивание у активной вкладки |
| Тревожные кнопки («нет контакта», «срыв звонка») | белый фон, **красная** рамка и текст |
| Нижняя полоса, вид оператора 112 | **оранжевый** |
| Нижняя полоса, вид ДДС | тёмно-серый |
| Таймер | чёрный блок, белые цифры |
| Строки ленты карточек | тёмный сине-серый, светлый текст |

Плотность высокая: интерфейс рассчитан на 1920×1080 без прокрутки основной части.
Шрифт — системный без засечек, признаки набраны строчными.

## 2. Верхняя полоса — телефония и идентификация

Слева направо:

1. **Кнопка отбоя** — иконка положенной трубки, отдельная ячейка.
2. **Состояние линии** — текст «не подключен»; под ним две кнопки: `записи звонков`, `список SMS`.
3. **АОН** — определившийся номер, маска `+7 ( ) - -`; иконки: «?» (справка), «пин» (геолокация), «глобус».
4. **предоставленный** — номер со слов заявителя; та же маска, кнопка `АОН` справа.
5. **телефон на место** — номер для обратной связи на месте происшествия; кнопка `АОН`.
6. **Идентификация карточки** — «Происшествие 913126», под ним «Сохр. 19.12.2022 в 09:04:37»
   и «Опер. 1002, АРМ 7, Системны…».
7. **Таймер** — чёрный блок, `00:16`, подписи «минут», «секунд».

В виде ДДС (стр. 23) вместо таймера — две кнопки: `просмотр` (синяя) и `дополнение` (тёмная).
Блоки 3–5 у каждого — своя иконка «сообщение» слева.

## 3. Левая колонка

### 3.1 Заявитель
Одна строка: поле `Фамилия и имя заявителя` · выпадающий список `выберите статус` ·
ещё один выпадающий список · кнопка транслитерации (иконка «Ха»).

В виде ДДС это read-only: «**Иванов**» и рядом серым «очевидец».

### 3.2 Адрес
Блок с заголовком `Адрес:` и иконкой карты (по клику открывается карта с точкой — по памятке).
Сверху — собранная строка адреса и крестик «очистить».

Поля, в том порядке и в той разбивке по строкам, как на скриншоте:

| Строка | Поля |
|---|---|
| 1 | `Страна` · `Субъект` · `Населенный пункт` |
| 2 | `Объект` · `Округ` (выпадающий) · `Район` (выпадающий) |
| 3 | `Улица` · `Дом/Вл` · `Корпус` |
| 4 | `Стр/соор` · `Квартира/офис` · `Подъезд` · `Этаж` · `Код` |
| 5 | `Описательный адрес` (во всю ширину) |

Справа внизу — кнопка `очистить адрес`.

> Поле **`Описательный адрес`** — прямое попадание в наш корпус билетов: там адрес
> почти всегда описательный («рядом с посольством Азербайджана на тротуаре»),
> а нормализованный дан отдельно. Это и есть пара «сказано → записано».

В виде ДДС адрес свёрнут в одну строку:
«Россия, Москва, (ЮАО, Чертаново Южное), Чертановская улица, 58, к. 2, под. 2».

### 3.3 Описание
`Описание со слов заявителя` — многострочное поле, плейсхолдер «введите»,
счётчик символов в правом нижнем углу, **лимит 1999** (`0 / 1999`).

## 4. Правая колонка — опросная карта и признаки

### 4.1 Верхний ряд флагов
Кнопки-тумблеры: `Пострадавшие` · `Нет на месте/Отказ от скорой` · `Нет доступа/Заблокированные`.
Правее, отдельной группой, красным: `нет контакта` · `срыв звонка`.

В виде ДДС это read-only строка: «Пострадавшие: нет  Отказ от скорой: нет  Заблокированные: нет»,
плюс кнопки `ЧС ⚡` и `ЧП ⚠` и карандаш.

### 4.2 Опросная карта
Серая полоса `добавить тип происшествия`, под ней вкладки открытых опросных карт
(на скриншоте одна — `Происшествие 101`).

Панель опросной карты: тёмный заголовок с названием и крестиком, далее строки
«подпись слева — ряд кнопок-признаков справа», с переносом кнопок на следующие строки.

Пример со скриншота (пожар):

| Подпись | Кнопки |
|---|---|
| `Где` | Улица · Транспорт · **Дом** · Здание/объект · Опасный объект |
| `Признак пожара (дом)` | Дым · **Открытое пламя** · Запах гари · Сработала пожарная сигнализация |
| `Доступ` | Нет доступа |
| `Дом (пламя)` | квартира · **балкон** · газовая колонка · газовая плита · лифт · мусоропровод · подъезд · счетчик электричества · частный дом · электрическая проводка · электрощит · лестничная клетка · подвал · дача · сарай/бытовка/хоз. постройка · прочие внутридомовые объекты |

**Это и есть каскад классификатора.** Подписи строк соответствуют уровням кода
`Г / п1 / п2 / п3`, а набор кнопок в строке — множеству значений уровня.
Следовательно, **панель опросной карты генерируется из `classifier.json`, а не верстается руками**:
из 1139 доступных оператору строк выводятся и состав кнопок, и порядок уровней,
и зависимость следующего уровня от выбранного предыдущего.

Названия признаков в интерфейсе и в классификаторе совпадают не буквально
(в UI — «Дом», в классификаторе — «жилой дом»), поэтому нужен слой соответствия
`ui_label ↔ код уровня`, тоже в данных.

### 4.3 Вид ДДС (read-only)
Вместо кнопок — готовый разбор:

```
▌Аварии и происшествия в городском хозяйстве     ← группа (тёмная полоса)
 Дерево. Двор (упало).                           ← выбранные признаки
 Класс.: Дерево упало во дворе;                  ← итоговый тип
 [ВИС] Класс.:                                   ← классификация от внешней системы
```

## 5. Нижняя полоса — список оповещения

### 5.1 Вид оператора 112 (оранжевая полоса)
Подпись `Службы:` и далее чипы служб, у каждого иконка телефона и крестик:
`Служба 102` · `Служба 101` · `ОМВД` · `ЦОДД` · `Мос.Без.` · `Упр. Южное М…` · кнопка `+`.

Справа: крупная кнопка `сохранить` и иконки — связанные карточки, таймер, оповещение,
комментарий, закрыть.

Список формируется **автоматически по ЕКП** из выбранных признаков — то есть у нас
его считает модуль `ekp`, и это же эталон для оценки маршрутизации.

### 5.2 Вид ДДС (тёмная полоса)
Блоки служб, каждый сворачивается/разворачивается шевроном. В свёрнутом виде показан
последний статус и его время: `Упр. Чертанов… / 13:22 Получена слу…`, `Преф. ЮАО / 11:59 Добавлена`.

В развёрнутом виде над полосой всплывает синяя панель с историей:

```
Упр. Чертаново Южное                              ✕
 оп. 14  ›  11:59:43  Добавлена
 оп. 0   ›  13:22:25  Получена службой
```

**Карандаш в правом верхнем углу блока своей службы** открывает проставление статуса —
ровно как описано в памятке. У чужих служб карандаша нет.

## 6. Проставление статуса реагирования

Над полосой служб раскрывается строка из четырёх элементов:

```
[ Принята            ▾ ] [ Номер наряда ] [ Направлены рабочие          ] [✓] [✕]
  ├ Принята
  └ Не принята
```

- **Выпадающий список** — только допустимые следующие статусы. На первом шаге ровно два:
  `Принята`, `Не принята`. После `Принята` — `Начало реагирования`, `Прибытие`,
  `Проведение работ`, `Завершение работ`, `Отказ от выполнения работ`.
  После `Не принята` — единственный вариант `Принята`.
- **`Номер наряда`** — текстовое поле.
- **Поле комментария** — на скриншоте заполнено «Направлены рабочие».
  Для `Не принята` и `Отказ от выполнения работ` комментарий **обязателен** (памятка).
- **✓** подтверждает (подсвечена оранжевой рамкой), **✕** отменяет.

Реализуется модулем `fsm`: таблица переходов — данные, обязательность комментария и
30-секундный норматив на первичный статус — правила на той же таблице.

## 7. Лента карточек (ПОВ-112)

Главный рабочий экран. Строка карточки, колонки слева направо
(расшифровка взята с аннотированного скриншота, стр. 13):

| # | Элемент | Назначение |
|---|---|---|
| 1 | `^` | открывает предпросмотр карточки |
| 2 | 🔗 | наличие связанных карточек (красная — есть) |
| 3 | 🔖 | закрепить карточку на экране |
| 4 | 📌 | важное происшествие (ставит Служба 112) |
| 5 | ⏱ | таймер |
| 6 | `900` | № оператора Службы 112 |
| 7 | `232` | № АРМ в Службе 112 |
| 8 | `37887393` | № карточки происшествия |
| 9 | `31.01.25` | дата создания |
| 10 | `10:47:38` | время создания (секунды — надстрочные, мельче) |
| 11 | `ДТП` | опросная карта, выбранная оператором 112 |
| 12 | `Нет` | наличие пострадавших |
| 13 | `Зарегистрирована` | статус карточки |
| 14 | `Москва, Третье транспортное кольцо, (ЮАО, Даниловский район), …` | адрес, с усечением |
| 15 | 📋 | индикатор контроля |
| 16 | ✅ | проверка карточки |

Развёрнутая строка — четыре подстроки с подписями слева:

```
Службы:     Служба 102 – 10:48:38 Получена службой,  ЦОДД – 10:49:05 Начало реагирования
Заявитель:  [ФИО] Александр Александрович  АОН +…  предоставленный телефон …
            Канал связи: МТС      Создание 00:00:59
Информация: Разлив топлива: Нет. Легковой транспорт. Нет пострадавших. ТС: … Кол-во а/м: 2.
Отработки:  Оп. 900 в 10:47:44 › Заявителю ›
```

- `Информация` — это **признаки происшествия в человекочитаемом виде**, собранные из опросной карты.
- `Отработки` — звонки оператора Службы 112.

**Карточка из внешней системы (ВИС) выглядит иначе** и это надо воспроизвести:
в колонке оператора — имя ВИС (`СОДЧ (…)`), **№ АРМ пустой**, **опросная карта пустая**,
а вместо строки `Информация` идёт строка `Описание` со свободным текстом и ФИО оператора ВИС.
По памятке у ВИС всегда «оп. 9999».

Карточки в статусах `Не оповещено`, `Отказ`, `Не завершено` — **ячейка статуса красная**.

## 8. Что из этого следует для реализации

1. **Опросная карта и лента генерируются из данных, а не верстаются.**
   Панель признаков — из `classifier.json`, строка ленты — из схемы карточки.
   Иначе 1139 комбинаций признаков придётся поддерживать руками.
2. **Нужен слой соответствия подписей** `ui_label ↔ уровень кода классификатора`:
   формулировки в интерфейсе и в классификаторе различаются.
3. **Две роли — два разных экрана.** Оператор 112 заполняет, ДДС читает и проставляет статусы.
   Общего кода у них меньше, чем кажется: у ДДС почти всё read-only.
4. **Карточки от ВИС — отдельный визуальный вариант**, и он несёт учебный смысл:
   у них нет формализованных признаков, только текст, и это осложняет работу диспетчера.
5. **Плотность и отсутствие прокрутки** — часть навыка. Верстаем под 1920×1080 как базовую,
   мобильную версию (её требует ТЗ) делаем для кабинетов и отчётов, но **не для АРМ-112**:
   тренажёр обязан воспроизводить рабочее место, а не адаптироваться под телефон.

# Часть II. По снимкам стенда 2026 и инструкции пользователя

## 10. Опросная карта: это теги с множественным выбором, а не строгий каскад

Главное уточнение к разделу 4.2. Опросная карта — это **список вопросов**, у каждого
свой тип ответа, и по многим вопросам **можно выбрать несколько значений сразу**.

Живой пример (`ui/2026/s112_04.png`, опросная карта «Происшествие 101»):

| Вопрос | Тип ответа | Значения (жирным — выбранные на снимке) |
|---|---|---|
| Где | один из | Улица · Транспорт · **Дом** · Здание / объект · Опасный объект |
| Признак пожара (дом) | один из | **Открытое пламя / Дым** · Запах гари · Сработала пожарная сигнализация |
| Доступ | флаг | Нет доступа |
| Дом (пламя, дым) | один из | **Дом многоквартирный** · Дом частный · Дача · Сарай / бытовка / хоз. постройка · Выселенное здание |
| Этажность здания | число | — |
| Угроза людям | да / нет | Да · Нет |
| Внутридомовые объекты (пламя, дым) | **несколько** | **Квартира** · Балкон · **Газовая колонка** · Газовая плита · Лифт · Мусоропровод · **Подъезд** · Счетчик электричества · Электрическая проводка · Электрощит · Лестничная клетка · Подвал · Прочие внутридомовые объекты · Крыша |
| Есть ли перекрытие движения | да / нет | Да · Нет |
| Проведена ли газификация | да / нет / нет данных | Да · Нет · Нет данных |
| Описание | текст | — |

**И вот как это стыкуется с классификатором.** Вопросы делятся на две группы:

- **Вопросы «что и где»** (`Где`, `Признак пожара`, `Дом (пламя, дым)`,
  `Внутридомовые объекты`) — это уровни кода `Г / п1 / п2 / п3`, они дают **итоговый тип**.
- **Вопросы да/нет** (`Угроза людям`, `Есть ли перекрытие движения`,
  `Проведена ли газификация`, `Доступ`) — это **условия маршрутизации**, то есть
  буквально колонки матрицы: в классификаторе они так и называются —
  `угроза людям`, `перекрытие движение`, `газификация`, `НД — нет доступа`.

То есть опросная карта и матрица маршрутизации — две проекции одной модели,
и обе генерируются из `classifier.json`. Догадка из раздела 4.2 подтвердилась
и уточнилась: генерировать надо не только состав кнопок, но и **тип вопроса**
(один из / несколько / да-нет / число / текст).

Типов опросных карт в системе — **около 50** (инструкция, раздел 4.2),
итоговых типов происшествия — 1283.

## 11. Выбор типа происшествия («Что случилось?», Alt+T)

Экран новой карточки (`ui/2026/s112_01.png`): строка `Введите тип происшествия`,
крупный заголовок `ЧТО СЛУЧИЛОСЬ?`, под ним плашки часто используемых типов:

```
ДТП · Ошибочно набран номер · 104 · Человек в опасности · Отмена вызова ·
Тестовый вызов · Передача дежурства · Консультация · Вызов на иностранном языке ·
Справка-101
```

Ниже — строка `Значимые типы происшествий:` (состав согласуется с руководством Службы 112).

Обратите внимание: половина часто используемых плашек — **не происшествия**
(`Ошибочно набран номер`, `Отмена вызова`, `Тестовый вызов`, `Передача дежурства`,
`Консультация`). Отсев непрофильных обращений — штатная и частая операция,
и в корпусе билетов такие вызовы есть.

Три способа выбора (инструкция): плашка частого типа, плашка значимого типа,
поиск по строке. **Можно выбрать несколько типов.** Поиск ищет по части слова,
слова вводятся в любом порядке, работают синонимы: «101» то же, что «пожар»,
а также «взрыв», «обрушение», «ДТП», «происшествие», «вызов 03», «запах газа»,
«авария», «авиакатастрофа», «выброс», «нападение».

## 12. Таймер и его красное состояние

Таймер в правом верхнем углу:

- **стартует при открытии новой карточки**, останавливается по кнопке «Сохранить»;
- время обработки сохраняется и **попадает в отчёты** — это ровно та метрика,
  которую ТЗ требует в отчёте о занятии;
- при превышении норматива набора **блок таймера становится красным**.
  На снимках: `00:09` — чёрный, `02:07` — красный.

Это второй таймер системы, не путать с 30-секундным нормативом на первичный
статус реагирования у службы-получателя (см. `ARCHITECTURE.md` §10.3).

Сопутствующее поведение статуса оператора телефонии:
`доступен` → при открытой карточке автоматически `недоступен` → после закрытия
карточки `недоступен` держится ещё **10 секунд** → снова `доступен`.

### 13.3 Список оповещения и история статусов
Полоса `Службы:` переносится на **несколько рядов**, когда служб много.
На снимке верхний ряд — территориальные (`ОАТИ`, `Поселение Ти…`, `Поселение Во…`),
нижний — основные (`Служба 101`, `Служба 104`, `Служба 102`, `Деп. ЖКХ`, `ЦЭМП`,
`ЦОДД`, `Мос.Без.`, `Мослифт`).

**Подчёркнута главная служба типа происшествия** — одна плашка. На снимках это `Служба 101`
для пожара: ровно значение колонки «Главная служба» классификатора (`MCHS`). Инструкция
говорит «основные службы подчёркиваются двойной линией»; на снимках линия одна.
Службы 104 и 102 не подчёркнуты, хотя получают карточку по своему классификатору.

Развёрнутая история статусов — синяя панель над полосой, по строке на статус,
с комментарием справа:

```
оп. 0 › 17.09.2026 11:14:04  Добавлена
оп. 0 › 17.09.2026 11:19:24  Получена службой
оп. 0 › 17.09.2026 11:23:21  Принята               › Отправлн сантехник для перекрытия воды
оп. 0 › 17.09.2026 11:29:04  Начало реагирования   › Сантехники приступили к работе по перекрытию воды в доме
```

Мелочь, которая многое говорит: в живых данных есть опечатка («Отправлн»).
Наш модуль проверки орфографии ровно это и ловит — и это реальный, а не выдуманный кейс.

## 16. Телефония: что именно надо эмулировать

Инструкция описывает телефонию **Avaya**; аппарат на рабочем месте —
**РТУ Т16Р** (даташит в комплекте): 20 SIP-линий, кодеки Opus, G.711a/u, G.722,
G.729AB, G.726, iLBC, AMR/AMR-WB, адаптивный джиттер-буфер до 300 мс,
DTMF RFC2833 / SIP INFO, двустороннее эхоподавление, два гигабитных порта, PoE,
до 106 DSS-клавиш.

Для `rtpd` это снимает неопределённость: **G.711a/u и Opus достаточно**,
DTMF через RFC2833, джиттер-буфер есть на стороне аппарата.

Функции, которые оператор реально использует и которые придётся эмулировать:

- **три режима перевода вызова**: «Перевести» (без проверки),
  «Перевести с удержанием» (оператор сначала дозванивается сам),
  «Добавить в конференцию»;
- **конференция** — до 4 участников в системе, до 6 на аппарате;
- исходящий вызов на АОН, на предоставленный номер, на телефон на место;
- перевод вызова на другого оператора по внутреннему номеру (например, `2407`),
  при этом у принявшего открывается карточка со всеми заполненными данными;
- удержание, отключение микрофона, переключение логических линий;
- **запись разговоров** с возможностью прослушать и скачать.

Перевод вызова в службу возможен **только при активном звонке заявителя и до
сохранения карточки** — отдельное правило, которое легко нарушить.

## 20. Окно карты (`s112_05`) — и связанный с ним риск

Карта открывается **отдельным окном браузера** с заголовком `С112 - карта`, не модально.
Панель инструментов:

```
[ Широта ] [ Долгота ] [ ОК ] [ Указать на карте ]        [ ⏱ 50 м ⌄ ] [ ≡ Слой ⌄ ]
```

Зум-контролы `+` / `−` слева, масштабная линейка внизу справа.
Радиус 50 м соответствует инструкции («камеры, техника и объекты в радиусе от 50 до 1000 м»).

**Подложка — Яндекс.Карты** (видны копирайт «© Яндекс», «Условия использования»
и логотип «Яндекс Карты»).

> **Риск, которого раньше не было в списке.** В изолированном контуре Яндекс.Карт нет.
> Значит для тренажёра нужна **офлайн-карта**: предзагруженные тайлы Москвы
> (OSM или иной источник, допускающий локальное размещение) плюс собственный
> слой объектов и радиусный поиск. Объём тайлов Москвы до 17-го зума — единицы гигабайт,
> что для нашего дистрибутива заметно. Варианты: ограничить зум, векторные тайлы,
> либо схематичная карта без подложки. Решение нужно принять до сборки инсталлятора.

## 22. Опросные карты: ещё два живых примера

### 22.1 «Происшествие 104» — газ (`s112_07`)

|---|---|

| Угроза людям | Да · Нет |

### 22.2 «П: Взрыв» (`s112_09`)

| Вопрос | Значения |
|---|---|
| Где взрыв | Здание / Объект · Транспорт · Звуки похожие на взрыв, что взорвалось сообщить не может |
| Есть возгорание | Да · Нет |
| Есть угроза обрушения | Да · Нет |
| Какие видят разрушения | текстовое поле |

Значения `Где взрыв` **дословно совпадают** со значениями `112-Признак.1` группы 3
классификатора («Взрыв объект», «Взрыв транспорт», «Звуки похожие на взрыв,
что взорвалось сообщить не может»). Это ещё одно прямое подтверждение,
что опросные карты порождаются классификатором.

Префикс `П:` в названии карты — по-видимому «Происшествие». Названия опросных карт
неоднородны: `Происшествие 101`, `Происшествие 104`, `П: Взрыв`.

## 23. Когда появляется список оповещения

Важная поведенческая деталь, которую видно только по серии кадров:

| Кадр | Выбрано | Службы внизу |
|---|---|---|
| `s112_07` | ничего (карта 104 открыта) | **пусто** |
| `s112_02` | Дом · Открытое пламя/Дым · Дом многоквартирный | **пусто** |
| `s112_04` | то же + Квартира · Газовая колонка · Подъезд | **8 служб** |

То есть **список оповещения не появляется, пока набор признаков не разрешается
в конкретный код классификатора**. Пока каскад неполон — маршрутизации нет.

Это же объясняет, почему подтянулась `Служба 104`: выбрана «Газовая колонка».
Подчёркнута только главная служба (`Служба 101`) — по колонке «Главная служба» классификатора.

## 24. Порог красного таймера

Собрал все наблюдения по кадрам:

| Кадр | Время | Цвет |
|---|---|---|
| `s112_01` | 00:09 | чёрный |
| `s112_09` | 00:32 | чёрный |
| `s112_06` | 00:44 | чёрный |
| `s112_07` | **01:03** | **чёрный** |
| `s112_02` | **01:23** | **красный** |
| `s112_04` | 02:07 | красный |
| `s112_03` | 02:38 | красный |

**Порог лежит между 63 и 83 секундами.** Ровно 60 секунд он не равен — это видно
из кадра `01:03`. Возможные объяснения: норматив 70–80 секунд, либо норматив
зависит от типа происшествия (кадры `01:03` и `01:23` — разные карточки и разные
опросные карты). Уточняется одним замером на стенде; в нашей реализации
делаем норматив **параметром схемы карточки**, настраиваемым преподавателем.

Побочное наблюдение: кнопки `нет контакта` и `срыв звонка` **становятся неактивными**
(бледнеют) после выбора типа происшествия — на пустой карточке они ярко-красные.

## 25. Проставление статуса реагирования: точная форма (`sdds_08`, `sdds_09`, `sdds_14`)

Строка раскрывается **над полосой служб**, во всю ширину, фон страницы затемняется.
Пустая форма:

```
[ Статус                    ▾ ]  [ Номер наряда ]  [ Комментарий ]  [✓]  [✕]
```

Заполненная (`sdds_09`):

```
[ Принята                   ▾ ]  [ 23 ]  [ Отправлн сантехник для перекрытия воды ]  [✓]  [✕]
```

`Номер наряда` **сохраняется между шагами** (на следующем статусе поле уже содержит `23`),
комментарий сбрасывается в плейсхолдер.

### Правило автомата, видимое напрямую

Кадр `sdds_14` — открытый список **после статуса «Начало реагирования»**:

```
Прибытие
Отказ от выполнения работ
Работы завершены
```

Сопоставив с историей (после «Прибытие» реально проставлено «Проведение работ»),
получаем правило:

> Доступны **следующий по порядку статус** и **два терминальных** —
> «Отказ от выполнения работ» и «Работы завершены».

То есть формулировку памятки «выбрать статусы можно только последовательно» надо читать
как «только вперёд»: перепрыгнуть к завершению можно, вернуться назад — нет.
Это ровно то, что реализует модуль `fsm`.

## 26. Эталонный трек статусов из живых данных (`sdds_10` … `sdds_20`)

Серия кадров даёт полную цепочку по службе «Поселение Вороновское»
на карточке 36814845 (`Класс.: пожар: квартира`):

```
11:14:04  Добавлена
11:19:24  Получена службой
11:23:21  Принята                 › Отправлн сантехник для перекрытия воды
11:29:04  Начало реагирования     › Сантехники приступили к работе по перекрытию воды в доме
11:32:13  Прибытие                › Дополнительно прибыли рабочие
11:33:40  Проведение работ        › Работы ведутся
11:34:51  Работы завершены        › Работы завершены
```

Плашка службы показывает **последний статус и его время** (`11:34 Работы завер…`),
панель истории скроллится, комментарий выводится справа от статуса через стрелку.

Три вещи, которые забираем в тренажёр:

1. Это **готовый эталонный трек** для теста автомата `fsm` и для демонстрации.
2. **Норматив 30 секунд нарушен**: от «Добавлена» (11:14:04) до «Принята» (11:23:21)
   прошло 9 минут 17 секунд. Живой пример нарушения №1 из таксономии памятки.
3. В комментарии есть опечатка «**Отправлн**». Модуль `spell` ловит ровно такое —
   и это настоящий случай из системы, а не придуманный.

## 27. Карточка у ДДС: свёрнутое и развёрнутое состояние (`sdds_06`, `sdds_12`)

В свёрнутом состоянии полоса служб — **один ряд** из восьми плашек
(`Служба 101`, `Служба 104`, `Служба 102`, `Деп. ЖКХ`, `ЦЭМП`, `ЦОДД`, `Мос.Без.`, `Мослифт`),
справа кнопка `⇅` (развернуть/свернуть все) и иконки сообщения и закрытия.

В кадрах с историей появляется **второй ряд** с территориальными службами
(`ОАТИ`, `Поселение Ти…`, `Поселение Во…`). По кадрам нельзя однозначно сказать,
добавились ли они позже или это перенос при разворачивании — при реализации
закладываем **перенос полосы на несколько рядов** как штатное поведение.

Карандаш редактирования есть **только у плашки своей службы**
(на кадрах — `Поселение Во…`), у остальных только шеврон разворачивания.

# Часть IV. Третья партия: «КАРТОЧКА 112» и «СЛУЖБЫ 112»

## 28. Опросная карта перестраивается от ответа на «Где»

Кадры `КАРТОЧКА 112` показывают карту «Происшествие 101» при `Где: Улица` —
и набор вопросов в ней **другой**, чем при `Где: Дом` (§10):

| Вопрос | Значения |
|---|---|
| Где | **Улица** · Транспорт · Дом · Здание / объект · Опасный объект |
| Признак пожара (улица) | Открытое пламя / Дым · Запах гари |
| Доступ | Нет доступа |
| Улица (пламя, дым) | Мусор · Трава, пух · Парк · Лес · Торф · Мачта освещения · Опора контактной сети · ЛЭП · Провода · Дерево, деревья · Горит человек · Что горит неизвестно |
| Место происшествия | Тоннель · Пешеходный переход |
| Угроза людям | Да · Нет |
| Правонарушение | Есть правонарушение |
| Медицинская помощь | Да · Нет |
| Требуется эвакуация | Да · Нет |
| Проведена ли газификация | Да · Нет · Нет данных |
| Описание | текст |

При `Где: Транспорт` третий вопрос — `Транспорт (пламя, дым)`: Общественный транспорт ·
Автомашина · ДТП с пожаром · Опасный груз; второй — `Признак пожара (транспорт)`:
Открытое пламя / Дым · Сработала пожарная сигнализация.

Итого: **опросная карта — условная форма**, вопросы второго и третьего уровня зависят
от ответа первого. Генератор формы из классификатора обязан это учитывать: вопрос
«что горит» строится из значений `п2` внутри выбранного `п1`.

Отдельный случай — **«Запах гари»**: код `1011100` разрешается сразу, вопроса «что горит»
нет, и служба назначается немедленно (кадр 29). Форма должна уметь «закрыться» раньше.

## 30. Справочник служб и две формы имени

Окно «Добавьте службы» прокручено на стенде целиком — 211 записей:
[`data/services/services.json`](../data/services/services.json).

У каждой службы две подписи, и в интерфейсе они используются в разных местах:

| Где | Пример |
|---|---|
| плашка в полосе служб | `Служба 104`, `Поселение Вороновское`, `Деп. Обр.` |
| окно «Добавьте службы» | `Служба 104 (АО "МОСГАЗ" Диспетчерское управление)`, `Поселение Вороновское (ДДС поселения Вороновское в городе Москве)` |

Порядок в окне — **не алфавитный** (например, `Служба 102` стоит в середине списка,
между районными ДДС) — это порядок записей в системе, воспроизводим как есть.
Одно полное наименование на снимке обрезано: `АСУ НС (Автоматизированная система управления …)`.

## 31. Серая плашка службы

В полосе служб одна плашка на всех снимках выделяется серым фоном — `Деп. ЖКХ`.
Классификатор эту службу для соответствующих кодов не выводит. Инструкция различает
цветом автоподбор и ручной выбор служб (в окне добавления: автоматически подобранные —
синие). Рабочая гипотеза — **серая плашка означает службу, добавленную вручную**;
вынесено вопросом заказчику. До ответа воспроизводим как отдельное визуальное состояние.
