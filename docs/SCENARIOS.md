# Формат сценариев

Сценарий — файл JSON: карточки или вызовы, которые получает обучающийся, и эталон — как правильно на них
реагировать. Режимов два: **действия с карточками** (диспетчер ДДС) и **карточки** (оператор Службы 112).
Встроенные сценарии лежат в `data/scenarios`; генератор преподавателя создаёт сценарии в том же формате.

Как добавить сценарий:

- **преподаватель** — «Сценарии» → загрузить файл JSON: сценарий появится черновиком с той же проверкой, что у
  встроенных, дальше — «Утвердить отмеченные»;
- **администратор** — «Настройки» → «Пакетное обновление сценариев»: zip с файлами `scenarios/*.json`, перед
  установкой — резервная копия;
- **разработчик** — файл в `data/scenarios`: сценарий загрузится при запуске сервера; тесты проверяют каждый
  встроенный сценарий.

Новые реплики заявителей и доклады бригады озвучиваются фоном после утверждения; пока реплика не озвучена, она
показывается текстом.

## 1. Сценарий ДДС

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | да | идентификатор: латиница, цифры, дефис, например `dds-shchukino-v0` |
| `title` | да | название в списках |
| `role` | да | служба, за которую работают обучающиеся, — точное название из справочника служб (`data/services`), например «Поселение Щукино» |
| `role_title` | нет | как роль показывается на экране: «ДДС района Щукино» |
| `place` | нет | район и округ для маршрутизации по территории: `{"district": "Щукино", "okrug": "СЗАО"}` |
| `reference` | нет | «Справка службы» для обучающихся: `{"title": …, "sections": [{"title": …, "items": […]}]}` |
| `source`, `note` | нет | происхождение сценария и пояснения |
| `cards` | да | карточки (таблица ниже) |

**Карточка:**

| Поле | Обязательно | Что это |
|---|---|---|
| `key` | да | ключ карточки, уникальный в сценарии: `A`, `B`, … |
| `at` | да | через сколько секунд от начала занятия карточка поступает (в темпе «реальное время») |
| `code` | да | код происшествия по классификатору, например `1051600` |
| `flags` | нет | признаки из классификатора (например, `ПП` — есть пострадавшие) |
| `caller` | да | заявитель: `name`, `status` (очевидец, пострадавший, …), `phone` |
| `address` | да | адрес: `street`, `house`, `korpus`, `stroenie`, `entrance`, `floor`, `flat`, `code` |
| `description` | да | описание оператора 112 |
| `manual_services` | нет | службы, которые оператор 112 добавил вручную (названия из справочника) |
| `chp` | нет | отметка «ЧП» оператора 112 |
| `brigade` | нет | доклады старшего бригады: `[{"after": 40, "status": "Начало реагирования", "text": "…"}]` — через сколько секунд после поступления карточки, какой статус должен поставить диспетчер и что говорит бригада |
| `expect` | да | эталон (таблица ниже) |
| `source` | нет | откуда пример (например, номер нарушения в памятке) |

**Эталон `expect`:**

| Поле | Что это |
|---|---|
| `primary` | правильный первичный статус: «Принята» или «Не принята» |
| `comment_facts` | обязательные сведения в комментарии к «Не принята»: список групп, в группе — варианты (основы слов); в комментарии должен быть хотя бы один вариант из каждой группы, словоформы учитываются. `{A}` — номер карточки A в занятии (для дублей) |
| `sample_comment` | образец комментария: показывается в разборе, его пишет автопилот `tools/demo_dds.py` |
| `final` | итоговый статус после докладов бригады: «Работы завершены» или «Отказ от выполнения работ» |
| `final_comment_facts`, `sample_final_comment` | то же для комментария к «Отказ от выполнения работ» |

Пример карточки, которую нужно не принять:

```json
{
  "key": "C", "at": 130, "code": "1051600", "flags": [],
  "caller": {"name": "Белов", "status": "очевидец", "phone": "+79990000103"},
  "address": {"street": "улица Рогова", "house": "17", "entrance": "1"},
  "description": "В подъезде уже полчаса воет пожарная сигнализация, дыма и запаха гари нет",
  "expect": {
    "primary": "Не принята",
    "comment_facts": [["пик"], ["передан", "сообщ", "направ", "звонил", "уведом"]],
    "sample_comment": "Дом обслуживает УК «ПИК», информация передана в их диспетчерскую +7 (999) 000-10-17."
  }
}
```

**Проверка при загрузке** (сценарий с ошибкой не загружается, причина указывается):

- ключи карточек не повторяются, служба `role` есть в справочнике;
- код есть в классификаторе, признаки известны, службы `manual_services` — из справочника;
- карточка доходит до службы `role` по классификатору (код, признаки, адрес) или вручную добавленной службой;
- первичный статус эталона — «Принята» или «Не принята»;
- статусы докладов бригады идут по автомату статусов (каждый допустим после предыдущего), а последний совпадает
  с `final`;
- ссылки `{A}` в сведениях указывают на существующие карточки.

## 2. Сценарий вызовов 112

| Поле | Обязательно | Что это |
|---|---|---|
| `id`, `title` | да | идентификатор и название |
| `mode` | да | `"cards"` |
| `norm_s` | нет | норматив заполнения карточки, с (80 по умолчанию) |
| `answer_norm_s` | нет | норматив принятия вызова, с (15 по умолчанию) |
| `duplicates` | нет | повторные вызовы о том же происшествии: `{"ключ вызова": "ключ исходного вызова"}` |
| `source` | нет | происхождение |
| `calls` | да | вызовы (таблица ниже) |

**Вызов:**

| Поле | Обязательно | Что это |
|---|---|---|
| `key` | да | ключ вызова, уникальный в сценарии |
| `situation` | да | ситуация одной строкой (для преподавателя) |
| `caller` | да | заявитель: `name`, `phone`, `gender` (`m` / `f` — голос озвучки) |
| `gold` | да | эталонная карточка (таблица ниже) |
| `dialogue` | да | ответы заявителя на вопросы оператора (таблица ниже); `opening` обязательна |
| `ticket` | нет | номер билета-источника |

**Эталон `gold`:**

| Поле | Что это |
|---|---|
| `codes` | допустимые коды происшествия (любой из них — верно) |
| `flags` | признаки, которые должны быть отмечены |
| `victims` | есть ли пострадавшие: `true`, `false` или `null` — не проверяется |
| `statuses` | допустимые статусы заявителя |
| `name` | ФИО заявителя |
| `address` | адрес: `subject`, `locality`, `street`, `house`, `korpus`, `stroenie`, `flat`, `entrance`, `floor`, `code`; `kw` — ключевые слова описательного адреса |
| `facts` | обязательные сведения описания: группы вариантов, как в `comment_facts` |

**Ответы заявителя `dialogue`** — по намерениям вопросов оператора (кнопки и распознанная речь):

| Ключ | Вопрос оператора |
|---|---|
| `opening` | первая реплика после принятия вызова |
| `details` | «Что случилось?», «Расскажите подробнее» |
| `address` | «Адрес?», «Где это?» |
| `address_clarified` | «Уточните адрес» и повторный вопрос об адресе |
| `name` | «Как вас зовут?» |
| `status` | «Кем приходитесь?» |
| `victims` | «Есть пострадавшие?» |
| `danger` | «Угроза людям?» |
| `gas` | «Газ?» |
| `access` | «Доступ?» |
| `phone` | «Телефон?» |

На вопрос без ответа в `dialogue` заявитель отвечает «Не понимаю вас. Повторите, пожалуйста».

**Проверка при загрузке:** ключи вызовов не повторяются; каждый код из `codes` виден оператору в типах вызова;
признаки, статусы заявителя и субъект адреса известны классификатору; первая реплика `opening` есть.
